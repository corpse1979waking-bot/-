## 📋 Новые команды для пользователей

### Базовые команды (доступны всем активным пользователям)

| Команда | Описание | Пример |
|---------|----------|--------|
| `/comment <id> <текст>` | Добавить комментарий к звонку | `/comment 15 Клиент перезвонит завтра` |
| `/view_comments <id>` | Просмотреть все комментарии | `/view_comments 15` |
| `/history <id>` | История изменений звонка | `/history 15` |
| `/my_calls [статус]` | Мои назначенные звонки | `/my_calls В работе` |

### Команды для операторов и админов

| Команда | Описание | Пример |
|---------|----------|--------|
| `/assign <call_id> <user_id>` | Назначить звонок на пользователя | `/assign 15 5` |
| `/status <call_id> <новый_статус>` | Изменить статус звонка | `/status 15 В работе` |
| `/overdue` | Показать просроченные звонки | `/overdue` |

### Команды только для администраторов

| Команда | Описание | Пример |
|---------|----------|--------|
| `/bulk_assign <user_id> <id1,id2,...>` | Массовое назначение | `/bulk_assign 5 10,15,20` |
| `/bulk_status <статус> <id1,id2,...>` | Массовая смена статуса | `/bulk_status Закрыт 10,15,20` |
| `/users` | Управление пользователями | `/users` |
| `/approve <user_id> [роль]` | Одобрить пользователя | `/approve 5 operator` |
| `/reject <user_id>` | Отклонить пользователя | `/reject 5` |

## 📊 Воронка статусов

Реализована валидная система переходов между статусами:

```
Новый → В работе → На связи → Закрыт/Не заинтересован
  ↓        ↓           ↓
  └──→ Отложен ←──────┘
```

**Нельзя перейти:**
- Из "Закрыт" в любой другой статус
- Из "Не заинтересован" в любой другой статус
- Из "Новый" сразу в "На связи" (только через "В работе")

## 📜 Audit Log (История изменений)

Каждое изменение логируется в таблице `audit_log`:

| Поле | Описание |
|------|----------|
| `action` | create, update, delete, status_change, assign |
| `field` | Какое поле изменено |
| `old_value` | Старое значение |
| `new_value` | Новое значение |
| `user_name` | Кто изменил |
| `created_at` | Дата и время |

**Пример вывода `/history 15`:**
```
📜 История звонка #15

👤 Алексей (15.03 14:30)
   Действие: create

👤 Мария (15.03 15:45)
   Действие: assign, Поле: assigned_to
   Стало: 5

👤 Алексей (15.03 16:20)
   Действие: status_change, Поле: status
   Было: Новый
   Стало: В работе

💬 Дмитрий (15.03 17:00)
   Действие: update, Поле: notes
   Было: 
   Стало: Клиент запросил КП
```

## 👥 Система ролей

| Роль | Права |
|------|-------|
| `admin` | Все операции, управление пользователями, массовые операции |
| `operator` | Назначение, смена статусов, комментарии, просмотр статистики |
| `guest` | Только просмотр, добавление комментариев |

**Статусы пользователей:**
- `pending` — ожидает одобрения админом
- `active` — активный пользователь
- `rejected` — отклонен

## 📈 Статистика

Команда `/stats` показывает:

**Общая статистика:**
- Всего звонков
- Распределение по статусам
- За сегодня/неделю/месяц
- Просроченные звонки
- Конверсия (%)

**Личная статистика (для операторов):**
- Создано звонков
- Назначено звонков
- Завершено звонков
- Конверсия выполнения (%)

## ⚠️ Просроченные звонки

Команда `/overdue` показывает звонки:
- У которых `remind_date` прошла, но напоминание не отмечено
- Которые в статусе "В работе" более 3 дней без изменений

## 💡 Сценарии использования

### Сценарий 1: Обработка входящего звонка
1. Оператор создает запись через `/new` или кнопку "📝 Новая запись"
2. Администрирующий видит новый звонок в `/list`
3. Администрирующий назначает звонок оператору: `/assign 15 5`
4. Оператор получает уведомление
5. Оператор меняет статус: `/status 15 В работе`
6. После разговора оператор добавляет комментарий: `/comment 15 Договорились о встрече`
7. Оператор закрывает звонок: `/status 15 Закрыт`

### Сценарий 2: Контроль просрочек
1. Администрирующий запускает `/overdue` каждое утро
2. Видит список просроченных звонков
3. Переназначает ответственных или меняет статусы

### Сценарий 3: Массовая обработка
1. Администрирующий выгружает список старых звонков
2. Массово закрывает: `/bulk_status Закрыт 100,101,102,103,104`
3. Массово назначает новых лидов: `/bulk_assign 5 200,201,202`

### Сценарий 4: Работа в команде
1. Новый сотрудник регистрируется через `/start`
2. Администрирующий видит заявку в `/users`
3. Администрирующий одобряет: `/approve 15 operator`
4. Сотрудник получает уведомление и начинает работу
5. Все действия сотрудника логируются в истории
